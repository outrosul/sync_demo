# 架构与命名规范

> 入口、硬约束见根 `AGENTS.md`。配套：约定细节 `docs/307_conventions.md`、命令与验证 `docs/301_workflow.md`。

## 一、分层总图

```
表现层 / 网络层（pygame 窗口 + socket 收发）
        ↑ 只读状态 / 收发协议消息
逻辑层 sync_demo/core/
        game  —— 世界状态、实体、规则（移动/跳跃/攻击/碰撞）
        sim   —— 确定性模拟（帧同步：tick 推演；状态同步：服务器权威推演复用同一 sim）
网络层 sync_demo/net/
        protocol —— 消息编解码（输入 / 快照 / 指令）
        server   —— 服务器进程（监听、调度、广播；含运行时切模式开关）
        client   —— 客户端进程（采样输入、渲染、按模式接入）
```

**一句话**：`core/` 是唯一的事实与规则来源；帧同步/状态同步是 `net/` 的两种「收集与分发」方式，切换不动 `core/`。

## 二、同步方式

| 方式 | 服务器做什么 | 客户端做什么 | 特点 |
| --- | --- | --- | --- |
| **帧同步 lockstep** | 收集每固定 tick 所有客户端的输入，按序号广播「指令帧」 | 只发输入；收到指令帧后用同一 `sim` 推演 | 权威在「一致性推演」，带宽小、延迟敏感 |
| **状态同步 state sync** | 服务器权威，用 `sim` 推演，定期广播权威快照 | 发送输入给服务器，插值/预测显示远端 | 权威在服务器，防作弊强、带宽较大 |

**切换**：服务器 console 输入 `mode lockstep` / `mode state`，运行时热切换，`net/server` 改分发改 `core/sim` 用法。

## 三、命名规范

- 变量/函数/文件 `snake_case`；常量 `UPPER_SNAKE`；单词 ≤20 字母、标识符 ≤4 单词、不用时态。
- 展示文本走 `text_key`（后续扩展），代码里不出现中文字面量。
