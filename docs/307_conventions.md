# 工程约定（硬规矩的「为什么」与细节）

> **正身**：`AGENTS.md` 只留一行一条的硬规矩（它每条消息都重发）；
> 「为什么这么定、具体怎么做、踩过什么」写在本册。两者冲突时以本册为准。

## 一、代码风格（强制）

- 禁止 `try/except` 包业务逻辑（用 `getattr`、`is None`、`if result` 判断）。
- 禁止 `lambda`（改名 `def`）。
- 所有 `import` 放文件顶部，不做函数内延迟导入。
- **注释与 docstring 一律中文**，与全仓库一致。
- 命名全 ASCII：变量/函数/文件 `snake_case`（≤4 单词）、常量 `UPPER_SNAKE`、标识符单词 ≤20 字母、不用时态。

## 二、分层原则

1. **逻辑层（`sync_demo/core/`）**：纯数据与规则，**不依赖渲染库、不依赖 socket、不取系统时间**。
   随机一律走**显式传入的随机源**，保证帧同步下两侧确定性一致。可脱离画面在测试里跑完整一局。
2. **表现层 / 网络层**：只读逻辑层输出的状态、按协议收发，不参与规则计算。
3. **同步方式与 gameplay 解耦**：帧同步 / 状态同步只是「网络层如何收集与分发输入/快照」，
   gameplay 核心同一套。切换模式不动 `core/`。

## 三、同步模式的确定性约束（本项目核心）

- **逻辑层任何运算不得依赖**：进程内全局随机（`random` 模块函数）、`time.time()` 等系统时钟、
  字典遍历顺序、对象 `id()`、浮点运算的跨平台差异。
- **随机一律用显式种子 RNG**：`random.Random(seed)`，seed 从协议层下发，两侧一致。
- **浮点坐标用整数定点**（如位置以「单位」存储并显式量化），避免 x87/SSE 差异导致 drift。

## 四、改动就要同步文档

- 每完成一点，同一轮改掉文档；重命名后旧名一起改（`grep` 全仓扫引用）。
- 文档与代码同轮跑测试。
- **做完功能，立即更新文档里的状态标注**：`docs/208_sync-references.md` 的「本 demo 现状」表、
  `docs/002_status.md` 的「已完成/待做」、第九清单的「✅/❌」，都要在功能落地**同一轮**改掉，
  不能出现「代码已实现、文档仍标 ❌ 缺」的过时状态（这是最容易漏、最会误导后来者的一种不同步）。

## 五、提交与改动方式

- `git commit` / `git push` 先经用户批准。
- 改文件用部分替换（锚点/patch），不全盘重写；新建文件才一次写全。

## 六、仓库布局

根只放入口：`AGENTS.md` / `README.md` / `requirements.txt` / `.gitignore` / 点文件 / 运行入口脚本。
代码在 `sync_demo/` 下按模块分子目录；测试在 `tests/`。

## 七、token 纪律

- 读大文档先 `grep` 定位再窗口读。
- `AGENTS.md ≤ 120 行`。
- sub-agent 只做并行探索/独立分析；串行任务在主会话做。
- 收尾即落盘。
- 给 agent 写文档：指针不副本、正面指令优先、no-op 剪枝。
